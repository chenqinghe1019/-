# 微小 → 抖小模型：原工作簿集成方案（2026-08-21）

## 最终 Excel 结构
在原《代号飞羽（微小）》工作簿基础上保留原 Sheet，并新增：
1. `代号飞羽（抖小预估）`：复制原模型结构，在原 LTV / 留存公式链路中嵌入渠道转换参数；
2. `新增流水表`：关联原表新增，按 Cohort × 生命周期 LTV 增量拆分自然月流水。

## LTV 公式集成
抖小 LTV 使用参考项目得到的绝对值系数：
- D1=0.6950
- D3=0.5736
- D7=0.5379
- D14=0.5100
- D21=0.5091
- D30=0.5031
- D45+长期=0.5050

原模型使用相邻阶段倍率，因此转换为阶段倍率修正：
- D3/D1：0.5736 / 0.6950 = 0.8253
- D7/D3：0.5379 / 0.5736 = 0.9378
- D14/D7：0.5100 / 0.5379 = 0.9481
- D21/D14：0.5091 / 0.5100 = 0.9982
- D30/D21：0.5031 / 0.5091 = 0.9882
- D45/D30：0.5050 / 0.5031 = 1.0038
- D60+：阶段倍率直接沿用微小，因为长期绝对值系数固定在约 0.505。

## 新增流水表
- 微小新增：直接关联原表第2行；
- 抖小新增：`微小新增 × 抖小/微小新增系数`，默认 1.00x；该系数只是场景输入，并非参考项目推导的固定渠道参数；
- 流水不重复乘留存，公式为 `Cohort新增 × 生命周期LTV增量`；
- 使用 D30、D60、D90……D1080 的累计 LTV 差额，生成 36 个生命周期月的 Cohort 流水，并平移到72个自然月；
- 分别生成微小、抖小 Cohort 流水矩阵与自然月汇总。

## 流水校验
按整30天月龄拆分时，单个自然月与原表可能因月内新增分布不同存在偏差；但微小累计重算内购流水约 237,257,222，原表累计约 237,077,078，累计偏差约 0.08%，说明 `新增 × LTV增量` 的总额口径与原模型高度一致。
