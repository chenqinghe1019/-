# 下方了：累计停留关卡与次日留存口径

## 适用场景

按新增第 N 天观察玩家停留关卡，并计算该批停留玩家在下一天是否留存。

## 核心定义

1. 样本底表必须是剔除“内充用户v2”后的全部新增玩家，不能先筛选 Dn 当天仍有战斗或仍活跃的玩家。
2. Dn 停留关卡取玩家从新增日至 Dn 截止的累计最高主线关卡（battle_type=1，事件取 battle_star、battle_result）。
3. 玩家 Dn 当天未登录或未发生战斗，也必须继续保留在 Dn 分母中，其停留关卡沿用此前累计最高关卡。
4. 从未进入主线的玩家单列为“未进入主线”。
5. 停留人数：截至 Dn 累计最高关卡等于该关卡的去重玩家数。
6. 停留占比：该关卡停留人数 / 同新增区间、同 Dn、同首日付费分层的全部新增玩家数。
7. 次日留存：Dn 停留玩家中，在新增日期 + N 天存在 in_out_log 的玩家数。
   - D1 对应 D2 留存。
   - D2 对应 D3 留存。
   - D3 对应 D4 留存。
8. 活跃表必须先按 #account_id + 自然日去重，再与停留快照关联。
9. 如果留存观察日为今天或未来，留存人数和留存率显示“-”。

## 重要反例

错误做法：先筛选 Dn 当天发生主线战斗的玩家，再计算 Dn 到 D(n+1) 留存。

该做法会提前排除 Dn 已流失、未战斗或未登录的玩家，使分母只剩高活跃用户，留存率被严重抬高，甚至大量出现 100%。
