# 下方了：高级抽阶段统计口径（2026-08-26）

## 字段与事件
- 事件：`recruit_log`。
- `gacha_type = 2` 为高级抽。
- 抽数使用 `recruit_log` 顶层事件属性 `gacha_num`，不要使用 `cardinality(award_ting)`、`count(*)` 或 `award_ting.gacha_num` 作为真实抽数。
- `award_ting` 仅用于拆英雄产出；`award_ting.type=2` 为英雄，英雄数量取 `award_ting.num`。

## 日期筛选
- `${PartDate:date1}`：新增日期筛选，基于用户表 `create_role_time` 转成 `$part_date` 后筛选。
- `${PartDate:date2}`：最终纳入报表的高级抽事件日期筛选。
- 玩家高级抽累计位置不能从 date2 起重新累计；应从玩家创角后历史高级抽开始累计，一直到 date2 范围内最后一个目标事件。

## 阶段判定
- 玩家历史高级抽累计抽数使用顶层 `gacha_num` 按 `#event_time` 顺序累计。
- 当前事件累计抽数 = 历史事件 `sum(gacha_num)`。
- 阶段沿用：`<350` = 350抽以前；`750~3499` = 750-3499抽；`3500~8499` = 3500-8499抽；350~749 不纳入当前阶段报表。
- 一条 `recruit_log` 可能拆出多条奖励，顶层 `gacha_num` 必须在拆数组前保留；拆数组后统计阶段实际抽数时，每条事件只计一次，不能因奖励行数重复累计。

## 指标
- 阶段实际抽数 = 当前阶段内高级抽事件顶层 `gacha_num` 之和。
- 阶段玩家数 = 当前阶段发生高级抽的去重玩家数。
- 人均产出数量 = 某阶段某英雄类型产出数量 / 该阶段玩家数。
- 平均多少抽产出1张 = 该阶段实际抽数 / 该阶段某英雄类型产出数量。
- 阶段内数量占比 = 某阶段某英雄类型产出数量 / 该阶段全部英雄产出数量。
