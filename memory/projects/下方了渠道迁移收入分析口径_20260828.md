# 下方了渠道迁移收入分析口径

更新时间：2026-08-28

## 项目与玩家口径
- 项目：下方了（数数 41）。
- 用户表：`ta.v_user_41`。
- 事件表：`ta.v_event_41`。
- 跨渠道玩家唯一标识统一使用 `nb_open_id`，不再使用 `if(open_id is null, nb_open_id, open_id)`。
- 活跃事件使用 `in_out_log`。
- 付费事件使用 `pay_log`，`payment` 单位为分，金额统计时 `/100` 转元。

## 渠道映射
- `3056220`：支付宝小游戏。
- `3056219`：官方Android渠道直播投放包。
- `3056215`：官方Apple渠道。
- `3056214`：抖音小游戏。
- `3056211`：微信小游戏。
- `3056210`：官方Android渠道。

## 微信收入大盘口径
微信收入分母只统计以下 4 个渠道：
- `3056211` 微信小游戏
- `3056210` 官方Android渠道
- `3056215` 官方Apple渠道
- `3056219` 官方Android渠道直播投放包

排除：
- `3056214` 抖音小游戏
- `3056220` 支付宝小游戏

微信安卓内购收入：上述 4 个微信体系渠道中 `system <> 'ios'` 的 `pay_log.payment/100`。
微信内购收入：上述 4 个微信体系渠道全部 `pay_log.payment/100`。

## 付费筛选
- 不限制 `change_reason`。
- 不限制 `pay_result`。
- 保留 `payment > 0`。
- 下方了无小黄车口径，因此不统计小黄车付费、微信小黄车收入、占总内购（包含小黄车）。

## tag 与渠道新增
- `active_channel`：同一 `nb_open_id` 下，按 `create_role_time` 最早角色对应的 `channel_id`。
- `event_channel`：玩家当天 `in_out_log` 实际上报的 `channel_id`。
- `active_channel = event_channel` 标记为 `纯新`。
- `active_channel <> event_channel` 标记为 `自有新增`。
- `渠道新增玩家数`：同一 `nb_open_id + event_channel` 的历史首次活跃日期等于统计日期的去重玩家数；它表示首次进入该行为渠道，不等同于首次创角新增。
- `DAU`：按 `日期 + tag + 行为渠道` 去重 `nb_open_id`。
- `内购流水`：按 `日期 + nb_open_id + 实际支付行为channel_id` 聚合后，与同日同 `nb_open_id + 行为渠道` 活跃关联，最终汇总到 `日期 + tag + 行为渠道`。

## 性能优化原则
- 不沿用步步旧版在大明细上多次 `window partition by` 的写法。
- 用户最初渠道优先使用 `min_by(channel_id, create_role_time)` 聚合。
- 历史首次进入渠道使用 `group by nb_open_id, channel_id + min($part_date)`，不在登录全明细上跑窗口。
- `in_out_log` 先压缩到 `日期 + nb_open_id + channel_id` 再参与 JOIN。
- `pay_log` 先压缩到 `日期 + nb_open_id + channel_id` 再参与 JOIN，避免登录明细与支付明细直接相乘。
- 微信大盘收入单独按日期聚合，分母仅扫描 4 个微信体系渠道。
