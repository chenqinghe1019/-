# 弯月勇者实测字段修正

更新时间：2026-08-31

## 表后缀
- 弯月勇者统一使用 `ta.v_user_44`、`ta.v_event_44`。
- 旧的 v46 记录作废。

## 事件表 domain 字段
埋点 Excel 中 `domain` 被定义为公共事件属性，但 Trino 实测事件视图中直接查询事件表 `domain` 会报列不存在。

因此弯月勇者 SQL 统一按以下规则处理：
- `ta.v_user_44`：使用 `domain='release'` 作为正式服 cohort 限制。
- `ta.v_event_44`：不要直接引用 `domain` 字段。
- 事件数据通过已筛选的正式服 `#account_id` cohort 关联。

## create_role_time
- `ta.v_user_44.create_role_time` 实测可能为 double/Unix 时间戳，不能直接 `date(create_role_time)`。
- 统一使用兼容解析：先尝试 timestamp，再尝试 Unix timestamp。

## 日期选择器
- `${PartDate:date}` 的业务含义统一为“新增日期 / 创角日期”。
- 只对由 `create_role_time` 派生出的 cohort `$part_date` 使用选择器。
- 不直接用同一个 `${PartDate:date}` 去筛 `pay_log`、`in_out_log`、`battle_result`。
- 事件扫描日期范围由所选新增 cohort 的最小/最大创角日期自动推导。

## 首日付费
- 事件：`pay_log`
- 金额字段：`payment`
- `payment` 实际单位需要 `/100` 后才是用于首日付费分层的金额。
- 首日付费金额：`sum(payment) / 100.0`。
- 首日判定使用 `date(#event_time) = create_date`。
- 分层：0；(0,6]；(6,30]；(30,100]；(100,300]；(300,500]；(500,1000]；>1000。

## 首日破冰付费时长
- 仅统计完整 D1 cohort，即 `create_date < current_date`。
- 破冰付费定义：创角当日第一笔 `pay_log` 且 `payment > 0`。
- 破冰付费时长：`create_role_time` 到首日第一笔付费 `#event_time` 的自然经过时长，单位分钟。
- 按每日新增 cohort 统计新增人数、破冰人数、破冰付费率、平均/中位破冰时长。

## 1-1 / 1-2 / 1-3 累计通关时长
- 事件：`battle_result`。
- 通关：`battle_result = 1`。
- 关卡：`map_id in ('1-1','1-2','1-3')`。
- 仅取创角当日首次通关该关卡的时间。
- 累计通关时长：`create_role_time` 到该关卡首次通关 `#event_time` 的自然经过时长，单位分钟。
- 人均累计时长只在已通关该关卡的玩家中取平均；同时可输出各关卡通关人数/通关率。

## 在线时长
- 事件：`in_out_log`
- 字段：`online_time`
- 单位：秒
- 登出时上报。
- 单条 `in_out_log` 的 `online_time > 86400`（超过24小时）视为异常记录，在线时长统计时剔除。
- `online_time = 86400` 保留；仅过滤严格大于24小时的记录。
- 玩家日在线时长：对有效记录按 `#account_id + date(#event_time)` 汇总 `sum(online_time)`，再除以 60 转分钟。

## Dn成熟口径
- D1 = 创角日，Dn目标日期 = `create_date + (n-1)`。
- 总新增玩家数不随 Dn 成熟度变化。
- Dn成熟新增玩家数、活跃、在线时长等 Dn 指标只计算目标日期 `< current_date` 的 cohort，避免把当天未结束数据算作完整成熟日。
