# 弯月勇者实测字段修正

更新时间：2026-08-31

## 表后缀
- 弯月勇者统一使用 `ta.v_user_44`、`ta.v_event_44`。
- 旧的 v46 记录作废。

## 事件表 domain 字段
埋点 Excel 中 `domain` 被定义为公共事件属性，但 Trino 实测事件视图中直接查询事件表 `domain` 会报列不存在。

因此弯月勇者 SQL 统一按以下规则处理：
- `ta.v_user_44`：使用 `domain='release'` 作为正式服 cohort 限制。
- `ta.v_event_44`：不要直接引用 `domain` 字段。
- 事件数据通过已筛选的正式服 `#account_id` cohort 关联。

## create_role_time / 新增账号口径
- `ta.v_user_44.create_role_time` 实测为可直接 `from_unixtime(create_role_time)` 的 Unix 时间戳口径。
- 新增账号口径优先参考线上漏斗 SQL：按 `nb_open_id` 取最早 `create_role_time`，得到 `openid_create_role_time` / `openid_create_role`。
- 角色事件仍通过 `#account_id` 关联，最终新增、漏斗、时长按 `nb_open_id` 去重。

## 日期选择器
- 线上漏斗模板中：`${Time:time2}` 用于新增日期 `date(openid_create_role)`；`${Time:time1}` 仅用于事件 `$part_date` 扫描范围；`${Text:text3}` 用于媒体平台。
- 若使用 `${PartDate:date}` 版本，则其业务含义统一为“新增日期 / 创角日期”，不要直接套到付费或战斗行为日期上。

## 首日付费
- 事件：`pay_log`。
- 金额字段：`payment`。
- `payment` 实际单位需要 `/100` 后才是金额；首日付费金额统计使用 `sum(payment) / 100.0`。
- 破冰付费判断只需 `payment > 0`。
- 首日判定：事件日期与 `openid_create_role` 同一天。
- 破冰付费时长：`openid_create_role_time` 到首日第一笔 `payment > 0` 的 `#event_time` 的自然经过时长，单位分钟。

## v44 主线关卡实际口径（2026-08-31 用户线上 SQL 校正）
- 主线战斗开始事件：`battle_start`，不是此前写的 `battle_star`。
- 主线战斗结算事件：`battle_result`。
- 关卡 ID 使用数值：
  - 1-1：`map_id = 10001`
  - 1-2：`map_id = 10002`
  - 1-3：`map_id = 10003`
  - 1-4：`map_id = 10004`
- 线上漏斗当前“战斗结算/通关节点”口径：只要出现对应 `battle_result + map_id` 即计入结算，不额外限制事件属性 `battle_result = 1`。
- 因此首日 1-1 / 1-2 / 1-3 累计时长，按 `openid_create_role_time` 到首日首次对应 `battle_result` 的 `#event_time` 计算。
- 如后续需求明确要求“严格胜利通关”而不是“结算到达”，需要再根据 v44 实际结果字段另加胜利条件，不能沿用之前错误的 `battle_result=1` 假设。

## 首日关卡 / 破冰时长报表
- 按每日新增 + 媒体平台统计。
- 新增人数沿用线上漏斗：D0 有登录行为的 `nb_open_id`。
- 输出 1-1 / 1-2 / 1-3 首日结算人数、结算漏斗率、人均累计时长，以及首日破冰付费人数、付费率、人均累计时长。
- 人均累计时长均先压成每个 `nb_open_id` 一条首日首次事件，再做平均，避免滚服/多角色导致重复加权。

## 在线时长
- 事件：`in_out_log`。
- 字段：`online_time`。
- 单位：秒。
- 登出时上报。
- 单条 `in_out_log` 的 `online_time > 86400`（超过24小时）视为异常记录，在线时长统计时剔除。
- `online_time = 86400` 保留；仅过滤严格大于24小时的记录。
- 玩家日在线时长：对有效记录按 `#account_id + date(#event_time)` 汇总 `sum(online_time)`，再除以 60 转分钟。

## Dn成熟口径
- D1 = 创角日，Dn目标日期 = `create_date + (n-1)`。
- 总新增玩家数不随 Dn 成熟度变化。
- Dn成熟新增玩家数、活跃、在线时长等 Dn 指标只计算目标日期 `< current_date` 的 cohort，避免把当天未结束数据算作完整成熟日。
